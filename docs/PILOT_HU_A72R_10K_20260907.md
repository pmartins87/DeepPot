# DeepPot HU pilot — A72r — 10k iterations/seed

Reference date: 2026-09-07

## Purpose

First stability probe of the new fixed-flop chance-sampled CFR+ prototype. This is not a strategy publication run. The goal is to measure whether the architecture can already reproduce a stable policy at modest sampling.

## Configuration

- Mode: true HU Pot Fold
- Canonical-style test flop: `Ah 7d 2c` (rainbow)
- Working pot rake: 2%
- Rake cap: none in this pilot
- Seeds: 1, 2, 3
- Iterations per seed: 10,000
- Chance sampling: private hands + turn + river sampled once per iteration
- Action tree: full binary FOLD/STAY traversal
- Update: CFR+ positive regret floor
- Averaging: linear

## Coverage

The fixed flop generated a union of 2,352 information-set keys across the three runs.

- seed 1: 2,351 infosets; median visits 8; min 1; max 19
- seed 2: 2,351 infosets; median visits 8; min 1; max 20
- seed 3: 2,352 infosets; median visits 8; min 1; max 19
- shared by all three seeds: 2,350 / 2,352 = 99.915% coverage

This confirms that 10k iterations gives almost complete *nominal* state coverage, but only very shallow sampling per exact infoset.

## Cross-seed policy differences

| Seeds | Mean abs Δ P(STAY) | P95 abs Δ | Max abs Δ | Greedy agreement |
|---|---:|---:|---:|---:|
| 1 vs 2 | 0.21399 | 0.58073 | 0.98108 | 71.87% |
| 1 vs 3 | 0.21403 | 0.57860 | 0.98251 | 72.27% |
| 2 vs 3 | 0.21748 | 0.57868 | 0.98482 | 71.08% |

Consensus metrics over infosets shared by all seeds:

- mean standard deviation of P(STAY): 0.13875
- P95 standard deviation: 0.30467
- max standard deviation: 0.43533
- all-seed greedy agreement: 57.62%
- classification: **UNSTABLE**

## Interpretation

The prototype has excellent state coverage but insufficient visits per exact information set. A median of eight visits cannot support a final exact-state policy, especially because turn/river are also sampled and therefore showdown value carries additional variance.

This is a useful result: it rejects the tempting but unsafe idea that a low-iteration all-flop run could already serve as DeepPot Base v1.

## Consequence for solver design

Before scaling to all 1,755 flops, improve one or more of the following:

1. substantially increase visits per infoset;
2. reduce terminal-utility variance with multi-runout or exact/cached showdown evaluation;
3. introduce a validated strategically safe state abstraction and refine only boundaries;
4. improve evaluator speed so exact/multi-runout estimates become affordable;
5. add HU best-response/exploitability validation independent of cross-seed agreement.

The current CFR engine remains a **research prototype**, not the final solver.
